## Notes

- `npm run build` joins `trader.slice` on the configured Linux lab, including the shared
  publisher's automatic builds. New scopes have a two-CPU/2 GiB ceiling inside the aggregate
  six-CPU/15 GiB budget. Builds already in the slice reuse it; other machines use Vite normally.
  If the configured lab's user manager is unavailable, the build fails instead of running unbounded.
- All data comes from the arena API, server-side through `$lib/server/arena.ts`. The browser never
  talks to the arena or to Capital.com. Mutations (broker mirror on/off, exclude a run) are form
  actions that send `ARENA_TOKEN`.
- Trade inspection reads use `$lib/server/inspection.ts` → loopback `trader-inspector:4140`,
  a separate bounded, read-only archive worker. Native and web share its stable trade keys, costs
  and coverage; missing quotes never become an exact intratrade risk claim.
- The native iPhone app reads `/api/native/v2/<screen>` (`src/routes/api/native/v2/[screen]`): each screen is built here
  (`$lib/server/native/screens.ts`, loaded by `load.ts`) in the format of `wire.ts`, gzip-compressed, with an ETag so
  an unchanged screen costs a 304. Chart series are packed base64 arrays. The device key, not the website login,
  authorizes these exact paths; `ops/server/native-access.py edge` lists them at the edge. Change a native screen
  here and push: no app build is needed unless the wire format changes.
- API types come from `@trader/shared` (`packages/shared/src/types.ts`); change them together with
  `apps/backend/src/arena/api.ts`.
- The leaderboard refreshes visible tabs every 30 seconds and retries failed loads after five seconds,
  without overlapping refreshes. Optional count/evidence outages preserve rows. A failed primary read
  may show an explicitly timestamped last-success summary for up to ten minutes. The server cache is
  memory-only, capped at six pages / 16 MiB serialized; it holds no orders, credentials or tick tape.
- Agent ids are `<file>` or `<file>/<variant>` (e.g. `ema-cross/fast`); demo run ids are
  `demo:<agentId>:<epic>:<codeHash>`.
- Pages: `/` leaderboard (Backtest, Virtual engine, Capital demo, Overfit views), `/agents`, `/agents/<id>` (versioned
  source), `/runs/<id>`, `/broker` (accounts, mirrored runs, deals), `/leverage`, `/journal`, `/research`
  (report, topic notes, library; files from `RESEARCH_DIR`, default `./research` in the UI runtime), `/status`,
  `/graveyard` (decommissioned agents, archived versions/runs, retirement reasons and platform history).
- Colors and chart styling come from the tokens in `src/app.css` (light and dark); use those rather
  than new hex values.

## Night Lab PWA

`/night-lab/` redirects to the standalone installable `/night-lab/index.html` page. It has its own
manifest and service-worker scope and uses the ordinary Trader hosting/authentication; it needs no
extra server. All clocks are New York time (16:00 close reference, 21:27 entry Mon–Thu, 02:27 exit).

It renders four current sections:
- **Matched 1:1 hold benchmarks** (`US500` and `US100` over `2024-01-01`–`2026-09-30`, zero funding).
- **20 forward experiments** (`research/night-cohort-v5-20261125.json`): NY-clock backtest metrics plus
  live virtual and Capital demo results polled from `/night-lab/forward.json` (schema 3, source-hash
  pinned, reading only the 20 cohort agents and shared across tabs for 20 s).
- **Direction controls**: same eligible nights as each index's base agent (previous day vs always long
  vs coin flip).
- **Nightly paper grid** (`/night-lab/grid.json`, built nightly by `apps/backend/src/lab/night-study/forward-grid.ts`
  and published to `trader-ui/night-grid/`): 540 NY-clock settings per index (`NY window × day filter ×
  overnight gap × leverage × side`) replayed from the first night after the backtest window.

Summary data (`src/lib/server/night-lab-summary.json` and `night-lab-cohort.json`) is generated by
`python3 ops/lab/build-night-lab.py` from the current NY-clock backtests and candle hold benchmarks,
served at `/night-lab/data/summary.json` via `src/lib/server/night-lab.ts` with ETag and Brotli/gzip
negotiation. The service worker (`static/night-lab/sw.js`) caches the shell, summary, last complete
forward snapshot and last complete grid offline. Generated data contains derived research and public
market facts only—never credentials, account identifiers or raw captured ticks.

## Develop

```sh
npm install                 # once, at the repo root (workspaces)
npm run dev                 # needs .env: ARENA_URL=http://127.0.0.1:4120 (the arena on this PC) and ARENA_TOKEN
npm run check               # svelte-check
npm run build               # adapter-node build in build/
```

## Deploy

Push `main`. The shared veron3 deploy watcher builds `apps/ui` from the committed source and publishes
to the PC runtime, restarting `pc-server-trader-ui.service`. The runtime and its `.env` live in
`<runtime>/trader-ui` (`<runtime>` from `ops/server/runtime.sh`); Hetzner hosts the public edge and
the real-money service, not the dashboard.
